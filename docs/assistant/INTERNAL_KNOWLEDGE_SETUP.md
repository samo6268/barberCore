# میمو با دانش داخلی — ارتقای مستقیم نسخه نصب‌شده

## نصب روی مک

این پچ روی نسخه دارای 0001، 0002 و 0003 اعمال می‌شود. پچ 0003 را Revert نکنید؛ بخش‌های مفید آن مانند ابزارهای مجاز، حافظه گفتگو، احراز هویت و منابع پاسخ حفظ می‌شوند و Provider پیش‌فرض عوض می‌شود.

```bash
cd ~/Projects/barbercore
git apply --check ~/Downloads/0004-Mimo-Internal-Knowledge-No-API.patch &&
git am ~/Downloads/0004-Mimo-Internal-Knowledge-No-API.patch
```

Migration یا نصب وابستگی جدید وجود ندارد. اجرای قبلی API و Web را با Ctrl+C متوقف کنید. زیرساخت و API:

```bash
docker compose -f infra/docker/docker-compose.yml up -d postgres redis
npm run dev --workspace api
```

در Terminal دیگری:

```bash
cd ~/Projects/barbercore
npm run dev --workspace web
```

بررسی وضعیت:

```bash
curl -sS http://localhost:4000/api/v1/assistant/status
```

مقادیر مورد انتظار داخل `data`:

```json
{
  "ready": true,
  "provider": "internal-knowledge",
  "mode": "read-only",
  "privateDataRequiresLogin": true,
  "externalModel": false,
  "requiresModelKey": false
}
```

`ready` وضعیت موتور داخلی است؛ سلامت دیتابیس و Redis باید جداگانه برقرار باشد. کلید و نام مدل لازم نیست. اگر متغیرهای `ASSISTANT_API_KEY`، `ASSISTANT_MODEL` یا `ASSISTANT_API_BASE_URL` را قبلاً وارد کرده‌اید، این نسخه آن‌ها را استفاده نمی‌کند. در صورت تمایل می‌توانید فقط همان سه خط را از `.env` و `apps/api/.env` حذف کنید؛ اطلاعات دیتابیس، JWT، Redis و سایر سرویس‌ها را حفظ کنید.

اگر گفتگوی قدیمی درباره اتصال مدل پیام خطا نشان داده است، پس از Restart، در میمو «گفتگوی تازه» را بزنید.

## توانایی‌ها

- راهنمای رزرو، ورود، جست‌وجوی شهر و نقشه، مدیریت سالن، خدمات، متخصص، تسویه و آکادمی.
- جست‌وجوی تطبیقی در مقالات همان کسب‌وکار؛ یکسان‌سازی حروف عربی/فارسی، اعداد و نیم‌فاصله.
- تشخیص نام شهر از فهرست ۱۰۹۳ نام یکتای موجود در داده مکانی همین پروژه؛ وجود نام شهر به معنی وجود سالن فعال نیست.
- نگهداری موضوع گفتگو، شهر، خدمت، سالن و گزینه‌های ارائه‌شده در Redis.
- خواندن قیمت‌ها و خدمات از ابزار زنده، با نمایش منبع و واحد مشخص.
- استعلام وقت آزاد؛ در درخواست «اولین وقت»، حداکثر هفت روز آینده بررسی می‌شود و این محدودیت صریحاً اعلام می‌شود.
- نوبت‌های شخصی با ورود معتبر، گزارش روزانه مالک و برنامه روزانه متخصص با مجوز سرویس دامنه.
- پاسخ روشن برای سؤال ناشناخته، داده ناموجود، تاریخ نامعتبر و خطای استعلام.

این موتور مدل زبانی نیست. جمله‌بندی‌های بسیار متفاوت یا چند درخواست پیچیده در یک پیام ممکن است تشخیص داده نشوند. در این حالت، سؤال را کوتاه‌تر و مرحله‌ای بپرسید. هیچ رزرو، لغو، پرداخت، ویرایش یا تغییر وضعیتی از گفتگو انجام نمی‌شود.

## سناریوهای پیشنهادی برای ارزیابی

۱. «چطور نوبت بگیرم؟» — باید راهنمای مستند با لینک ارائه شود و هیچ مدل خارجی فراخوانی نشود.

۲. «سالن برای کوتاهی مو می‌خواهم» ← «تهران» ← «گزینه دوم» ← «اولین وقت خالی» — باید شهر و خدمت حفظ شوند، سالن از نتیجه واقعی انتخاب شود و استعلام وقت برای همان سالن و خدمت انجام شود. در دیتابیس خالی یا نبود گزینه دوم، باید نبود نتیجه یا نامعتبر بودن انتخاب اعلام شود.

۳. «نوبت‌های من» در حالت مهمان و پس از ورود — حالت مهمان باید درخواست ورود کند و حالت واردشده فقط اطلاعات خودش را بخواند.

۴. «خلاصه وضعیت امروز» با نقش مالک — در صورت داشتن چند سالن ابتدا انتخاب سالن انجام می‌شود. کاربر مشتری نباید به این آمار دسترسی داشته باشد.

۵. «در این صفحه چه کارهایی می‌توانم انجام بدهم؟» در پنل متخصص و تسویه — پاسخ باید متناسب با صفحه باشد.

۶. سؤال نامرتبط — پاسخ نامطمئن یا مقاله تصادفی نباید نمایش داده شود.

## منبع دانش و به‌روزرسانی

دانش فعلی در `apps/api/src/modules/assistant/assistant-business.service.ts` تعریف شده است. هر مقاله شناسه، عنوان، متن پاسخ، کلیدواژه‌های مترادف و مسیر منبع دارد. متن‌ها برای نمایش مستقیم به کاربر نوشته شده‌اند.

تغییر امکانات یا قوانین باید با اصلاح مقاله مربوط همراه شود. کد و صفحات به‌صورت خودکار به دانش تبدیل نمی‌شوند و موتور متن آزاد اینترنت را نمی‌خواند. اطلاعات متغیر مثل قیمت، وضعیت نوبت و موجودی از دیتابیس دوباره خوانده می‌شوند؛ حافظه جای داده زنده یا مجوز را نمی‌گیرد.

موتور گفتگو در `providers/internal-knowledge.provider.ts` است. افزودن نوع سؤال تازه نیازمند تعریف Intent و قالب خروجی قابل تست است. مدل خارجی در `AssistantModule` ثبت نشده؛ وجود فایل Adapter قدیمی باعث تماس شبکه نمی‌شود.

## کسب‌وکار دیگر

همان Web Component یا React Adapter قابل استفاده است. Business Manifest ظاهر و واژگان را تعیین می‌کند. دانش سمت سرور از تنظیم زیر خوانده می‌شود:

```dotenv
ASSISTANT_BUSINESSES_JSON='[{"assistantId":"example-app","name":"سامانه نمونه","description":"راهنمای خدمات سازمانی","knowledge":[{"id":"requests","title":"ثبت درخواست","text":"درخواست را از صفحه درخواست‌ها ثبت کنید.","keywords":["ثبت درخواست","درخواست جدید"],"path":"/requests"}]}]'
```

ویجت همان کسب‌وکار باید `assistantId="example-app"` داشته باشد. محتوای پرنگارین و ابزارهای سالن برای این کسب‌وکار فعال نمی‌شوند. برای داده زنده هر محصول جدید، ابزار و احراز هویت همان محصول باید به Registry اضافه شود؛ هویت اعلام‌شده مرورگر مجوز نیست. CORS دامنه نیز باید مجاز باشد.

## کنترل دسترسی و نگهداری داده

کنترل JWT، نقش فعلی، مالکیت و عضویت سرویس‌های دامنه حفظ شده است. داده و Context به ارائه‌دهنده مدل خارجی فرستاده نمی‌شود. اطلاعات می‌تواند بین مرورگر و API خود سامانه و Redis/PostgreSQL همان زیرساخت جابه‌جا شود.

تاریخچه با انقضای یک ساعت و حداکثر ۱۲ پیام اخیر نگهداری می‌شود. State ساختاریافته سمت سرور ذخیره می‌شود، از متن یا شناسه دلخواه کاربر مجوز استخراج نمی‌شود. سهمیه روزانه و Rate Limit برای جلوگیری از فشار بر زیرساخت باقی مانده‌اند؛ به هزینه API مدل مربوط نیستند.
