# بازنگری میمو: راهنمای فرایندی و فهم زبان با مدل محلی

تاریخ بررسی: ۳ نوامبر ۲۰۲۶. این سند وضعیت کد و حدود نسخه تحویلی را توضیح می‌دهد؛ فعال‌شدن در سرور و کیفیت مدل واقعی باید جداگانه تأیید شوند.

## نتیجه بررسی

موتور قبلی یک راهنمای قاعده‌محور با جست‌وجوی کلیدواژه بود. این شیوه برای FAQ و استعلام‌های ازپیش‌تعریف‌شده مفید است، اما درک عمومی زبان، تشخیص صورت‌بندی‌های متفاوت سؤال و شناخت مرحله واقعی فرم را فراهم نمی‌کند. خواندن کد سایت هم به‌خودی‌خود یک مدل زبانی آموزش‌دیده ایجاد نمی‌کند.

نسخه جدید دو لایه دارد:

| لایه | مسئولیت | نیاز به مدل |
|---|---|---|
| راهنمای قابل اتکا | مراحل واقعی صفحه، موانع فرم، توضیح اصطلاحات، پیوند منبع و استعلام ابزارهای مجاز | ندارد |
| فهم زبان | تبدیل سؤال و سابقه گفت‌وگو به یک درخواست ساختاریافته از مجموعه مجاز | اختیاری، Ollama روی زیرساخت خودمان |

مدل جای پایگاه داده، احراز هویت، منطق کسب‌وکار یا کنترل وضعیت را نمی‌گیرد. به‌جای تولید آزاد اعداد و سیاست‌ها، یک برنامه JSON محدود انتخاب می‌کند و پاسخ از مقاله ثبت‌شده یا سرویس دامنه ساخته می‌شود. این انتخاب، احتمال پاسخ روان ولی بی‌پشتوانه را کاهش می‌دهد؛ انتخاب اشتباه موضوع توسط مدل همچنان ممکن است و باید با سؤال‌های فارسی واقعی سنجیده شود.

## آنچه پیاده شده است

- راهنمای مرحله‌ای برای رزرو، کشف مرکز، صفحه مرکز، ثبت واقعی سالن، مدیریت خدمات، کارکنان، تنظیمات، نوبت‌ها، گزارش، تسویه، ورود، حساب و آکادمی.
- نمایش کارت مراحل، مرحله فعلی و پیشنهاد ادامه گفت‌وگو در React Adapter؛ نمایش مراحل و استفاده از Context SDK در Web Component.
- دریافت وضعیت فرم برای رزرو، دو مسیر ثبت/معرفی سالن، ورود مشتری و متخصص و برنامه کاری متخصص. در بقیه صفحات، راهنما از مسیر ثبت‌شده استفاده می‌کند؛ میمو خودکار وضعیت تمام فیلدها را نمی‌خواند.
- تشخیص موانع مشخص مثل انتخاب‌نشدن موقعیت نقشه، نبود خدمت یا روز، نبود متخصص واجد شرایط، خطای دریافت وقت، نبود ساعت آزاد، خطای ذخیره، ارسال/تأیید ناموفق کد و بازه کاری نامعتبر.
- جداسازی «راهنمای مراحل» از «وضعیت صفحه هنگام پاسخ»؛ پیشرفت توضیحات در گفتگو به معنی تکمیل فرم نیست.
- مقایسه حداکثر سه مرکز از نتایج واقعی گفتگو با خواندن دوباره خدمات، قیمت، مدت و نظرها. بدون داده مکانی معتبر، فاصله یا «بهترین مرکز» حدس زده نمی‌شود.
- بررسی Redis در وضعیت سلامت؛ آماده‌بودن صرفِ موتور دیگر برای `ready=true` کافی نیست.
- اتصال اختیاری به API بومی Ollama، بدون OpenAI SDK، کلید OpenAI یا مسیر جایگزین به سرویس OpenAI.
- محدودیت یک درخواست مدل هم‌زمان در هر پردازش API، مهلت پاسخ محدود و بازگشت به راهنمای داخلی در شکست یا خروجی نامعتبر مدل.

## یافته‌های مهم درباره خود سامانه

۱. `/dashboard/salons/new` مسیر دارای فراخوانی واقعی ثبت سالن است. `/salons/new` در کد بررسی‌شده یک معرفی چندمرحله‌ای است که به صفحه موفقیت می‌رود و فراخوانی ثبت سالن ندارد. میمو این دو را یکسان معرفی نمی‌کند.

۲. ورود و بخش‌هایی از `apps/admin` نمونه نمایشی‌اند و اعداد ثابت دارند. آمار نمایشی نباید به‌عنوان داده واقعی وارد پاسخ دستیار شود. برای این پنل یک دستیار راهنمای مستقل با شناسه `parnegarin-admin` اضافه شده که این محدودیت را توضیح می‌دهد؛ هیچ نقش ادمین، توکن یا دسترسی خصوصی از ورود نمایشی تولید نمی‌شود. اتصال احراز هویت و داده واقعی ادمین پروژه‌ای جداست.

۳. ابزار زنده آکادمی، محاسبه فاصله شخصی کاربر، تحلیل تمام بازه‌های خالی و عملیات نوشتنی در گفتگو فعال نیستند. پیشنهادهای رابط که فراتر از توان واقعی بودند اصلاح شده‌اند.

## مسیر پاسخ

۱. اعتبارسنجی درخواست، احراز هویت و خواندن نقش جاری کاربر از پایگاه داده.
۲. بازیابی گفت‌وگوی محدود و جداشده هر حساب/مهمان در Redis.
۳. اگر درخواست راهنمای همان فرم است، تطبیق با فرایند ثبت‌شده و کد موانع صفحه؛ پاسخ بدون انتظار برای مدل.
۴. اگر مدل محلی فعال است، فهم سؤال با JSON Schema و اعتبارسنجی مجدد خروجی. شناسه مقاله و فرایند باید ثبت‌شده باشد؛ شهر و تاریخ نباید ساخته شوند.
۵. پاسخ از دانش معتبر یا فراخوانی ابزار دامنه. کنترل مالکیت و نقش در ابزارها باقی می‌ماند.
۶. بازگرداندن متن، منابع، کارت راهنما و پیشنهاد ادامه؛ ذخیره سابقه محدود گفتگو.

مدل هیچ SQL، نام ابزار دلخواه، لینک خارجی، مجوز یا عملیات نوشتنی را اجرا نمی‌کند. متن آزاد خروجی مدل نیز مستقیم به‌عنوان پاسخ منتشر نمی‌شود.

## شناخت صفحه و حریم خصوصی

Context SDK به‌صورت صریح فقط شناسه فرایند، شناسه مرحله، مراحل انتخاب‌شده و کد موانع را منتشر می‌کند. مقادیر فرم، شماره تلفن، ایمیل، آدرس، رمز، کد پیامکی، کوکی و توکن از فرم خوانده نمی‌شوند. در مثال زیر، فقط شناسه‌ها منتقل می‌شوند:

```ts
import { publishAssistantWorkflow } from '@adaptive-assistant/core';
const cleanup = publishAssistantWorkflow('/requests/new', {
  id: 'request-create',
  stepId: 'details',
  completed: ['type'],
  issues: [],
});
// هنگام خروج از صفحه:
cleanup();
```

میزبان باید فرایند را در تنظیمات معتبر سمت سرور ثبت کند. فرایند منتشرشده از مرورگر فقط وقتی برای پیشرفت فرم استفاده می‌شود که شناسه‌اش با فرایند همان مسیر تطبیق داشته باشد. Context مرورگر مجوز دسترسی نیست و تکمیل فیلد هم به معنی ذخیره قطعی در پایگاه داده نیست.

در صورت فعال‌بودن Ollama، متن پیام‌های اخیر برای مدل خودمیزبان ارسال می‌شود. شماره همراه، ایمیل و توکن JWT قابل تشخیص پیش از این ارسال حذف می‌شوند؛ این پالایش جایگزین خودداری کاربر از نوشتن اطلاعات محرمانه نیست. متن و پاسخ خام مدل در لاگ خطا ثبت نمی‌شوند. حافظه گفت‌وگو برای آموزش خودکار مدل استفاده نمی‌شود.

## استفاده در کسب‌وکار دیگر

`ASSISTANT_BUSINESSES_JSON` علاوه بر دانش می‌تواند `workflows` داشته باشد:

```json
[{
  "assistantId": "another-app",
  "name": "سامانه دیگر",
  "knowledge": [{"id":"intro","title":"معرفی","text":"راهنمای معتبر سامانه","path":"/"}],
  "workflows": [{
    "id":"request-create", "title":"ثبت درخواست", "path":"/requests/new",
    "paths":["/requests/new"],
    "steps":[
      {"id":"type","title":"نوع درخواست","instruction":"نوع درخواست را انتخاب کنید."},
      {"id":"details","title":"جزئیات","instruction":"اطلاعات لازم را در فرم تکمیل کنید."}
    ]
  }]
}]
```

مسیرهای دقیق و الگوی پایانی `/*` پشتیبانی می‌شوند. این دانش و مراحل باید در سرور توسط مالک کسب‌وکار نگهداری شوند؛ صفحات و پیام‌های کاربران منبع قوانین جدید نیستند. ابزارهای خصوصی هر سامانه باید مستقل با احراز هویت و مجوز آن سامانه اضافه شوند؛ ابزارهای سالن برای کسب‌وکار دیگر فعال نمی‌شوند.

## انتخاب مدل و ظرفیت

گزینه اولیه برای آزمون، `qwen3:4b-instruct-2507-q4_K_M` است. خانواده Qwen3 از فارسی پشتیبانی می‌کند؛ فایل این مدل در فهرست Ollama حدود ۲٫۵ گیگابایت است. حجم فایل، میزان RAM لازم یا تضمین کیفیت فارسی نیست. اندازه زمینه، حافظه اجرای مدل، سیستم‌عامل، PostgreSQL، Redis و برنامه‌ها نیز RAM مصرف می‌کنند.

آخرین مشخصات اعلام‌شده سرور پرنگارین حدود ۸ گیگابایت RAM و اجرای هم‌زمان برنامه و پایگاه داده بود. فعال‌سازی مدل روی همین سرور بدون سنجش حافظه و تأخیر توصیه نمی‌شود. ابتدا روی دستگاه توسعه یا میزبان آزمایشی تست شود. در نسخه آماده‌شده، مدل به‌صورت پیش‌فرض خاموش است و نصب Ollama خودکار انجام نمی‌شود.

معیار پذیرش مدل: درست‌فهمیدن سؤال‌های محاوره‌ای فارسی، حفظ شهر/خدمت/گزینه در ادامه گفتگو، انتخاب درست منبع، پرهیز از ساخت تاریخ و شهر، رفتار امن در سؤال نامرتبط و زمان پاسخ قابل قبول در کنار بار واقعی برنامه. این نسخه هنوز بنچمارک مدل واقعی روی سرور شما ندارد.

## نصب و بررسی

این تغییرات migration، seed و تغییر رمز پایگاه داده ندارند. تنظیمات معتبر سرور و تغییرات محلی Docker را حفظ کنید. روی سرور از `git reset --hard`، حذف volume و اجرای seed برای این ارتقا استفاده نشود.

پس از اعمال پچ روی کد به‌روز:

```bash
node scripts/prepare-mimo-contextual.mjs
npm ci
npm test --workspace api -- --runInBand src/modules/assistant
node --test packages/assistant-core/test/*.test.cjs
npm run build --workspace api
npm run build --workspace web
npm run build --workspace admin
```

در PowerShell می‌توانید `npm.cmd` را جایگزین `npm` کنید. اسکریپت آماده‌سازی فقط ناسازگاری قدیمی `.at(-1)` با ES2021 را به‌صورت تکرارپذیر اصلاح می‌کند؛ `.env` را تغییر نمی‌دهد.

حالت پیش‌فرض:

```dotenv
ASSISTANT_REASONING_MODE=rules
```

در این حالت، راهنمای فرم، کارت مراحل، دانش داخلی، مقایسه و ابزارهای مجاز فعال‌اند؛ فهم عمومی مدل زبانی اضافه نشده است.

برای آزمون روی دستگاه توسعه‌ای که Ollama روی آن نصب است، ابتدا وزن مدل دانلود و سرویس محلی اجرا شود. مطابق سیستم‌عامل، تنظیم محلی `OLLAMA_NO_CLOUD=1` را روی خود فرایند/سرویس Ollama اعمال کنید:

```bash
ollama pull qwen3:4b-instruct-2507-q4_K_M
```

سپس در فایل محیطی API همان محیط:

```dotenv
ASSISTANT_REASONING_MODE=ollama
ASSISTANT_OLLAMA_URL=http://127.0.0.1:11434
ASSISTANT_OLLAMA_MODEL=qwen3:4b-instruct-2507-q4_K_M
ASSISTANT_OLLAMA_TIMEOUT_MS=15000
```

برای API داخل Docker، آدرس میزبان از دید خود کانتینر تعیین شود؛ `localhost` داخل API به کانتینر Ollama اشاره نمی‌کند. هاست‌های loopback، `ollama`، `host.docker.internal` و IP خصوصی پشتیبانی می‌شوند؛ دامنه عمومی و تگ مدل cloud رد می‌شوند.

فایل اختیاری `infra/docker/docker-compose.mimo-model.yml` یک Ollama جدا با پورت محدود به localhost، شبکه موجود برنامه، cloud غیرفعال، سقف حافظه ۴ گیگابایت و یک درخواست هم‌زمان تعریف می‌کند. `deploy-mimo.sh` آن را خودکار اجرا نمی‌کند. سقف حافظه تضمین اجرا نیست؛ OOM یا کندی باید در آزمون مشخص شود. ایمیج مشخص‌شده در این محیط ساخته یا اجرا نشده است.

فقط پس از ارزیابی ظرفیت روی میزبان آزمایشی دارای شبکه برنامه:

```bash
docker compose -f infra/docker/docker-compose.mimo-model.yml up -d ollama
docker compose -f infra/docker/docker-compose.mimo-model.yml exec ollama ollama pull qwen3:4b-instruct-2507-q4_K_M
```

در آن حالت، آدرس API به Ollama برابر `http://ollama:11434` است. تنظیمات mode باید در محیط API اعمال و خود API بازآفرینی شود. فعال‌کردن مدل در پنل عمومی مرورگر انجام نمی‌شود.

بررسی سلامت:

```bash
curl -sS http://127.0.0.1:4000/api/v1/assistant/status
```

`ready` سلامت موتور و حافظه گفتگو را نشان می‌دهد. `understanding` حالت تنظیم‌شده را مشخص می‌کند. `localModelState` ابتدا `unverified` است و تنها پس از یک پاسخ ساختاریافته معتبر `available` می‌شود؛ `invalid-output` یا `unavailable` به معنی استفاده از مسیر داخلی است. آماده‌بودن راهنمای داخلی به معنی تأیید کیفیت یا سرعت مدل نیست.

برای پنل ادمین، بازنویسی داخلی Next مسیر دستیار را به `ASSISTANT_API_ORIGIN` می‌فرستد؛ پیش‌فرض `http://127.0.0.1:4000` است. در میزبانی جدا/کانتینر، این origin سمت سرور را مطابق شبکه خصوصی تنظیم کنید. ورود نمایشی ادمین هیچ توکن خصوصی به این مسیر نمی‌دهد.

## سناریوهای پذیرش

| سؤال/موقعیت | پاسخ قابل قبول |
|---|---|
| رزرو، خدمت انتخاب نشده، «الان چه کار کنم؟» | مرحله انتخاب خدمت و مانع همان صفحه، بدون ادعای ثبت |
| رزرو، روز انتخاب شده، زمان آزاد نیست | پیشنهاد بررسی روز/متخصص دیگر، تفکیک نبود وقت از خطای دریافت |
| «مرحله بعد» در فرم ناقص | راهنمای همان مرحله؛ فرم جلو نرود |
| ادامه توضیح بدون Context فرم | ادامه راهنمای مراحل با حافظه؛ تکمیل واقعی فرض نشود |
| ثبت سالن، نقطه نقشه انتخاب نشده | راهنمای انتخاب نقطه و تفاوت آن با انتخاب شهر |
| «ثبت سالن شد؟» در مسیر معرفی نمایشی | توضیح محدودیت و لینک ثبت واقعی؛ ادعای ثبت ساخته نشود |
| ورود ناموفق | تفکیک ارسال ناموفق کد از تأیید ناموفق؛ نپرسیدن رمز/کد در چت |
| «برنامه شخصی‌ام را ببینم» با فهم مدل | استعلام نوبت‌های همان حساب؛ مهمان نیازمند ورود |
| مدل برای مشتری برنامه مالک انتخاب می‌کند | مجوز مالک جعل نشود و ابزار خصوصی اجرا نشود |
| مقایسه دو مرکز | قیمت و نظر واقعی؛ مبنای خدمت مشابه؛ فاصله و کیفیت تضمینی ساخته نشود |
| آمار ادمین | اعداد نمایشی به‌عنوان آمار واقعی پاسخ داده نشوند |
| خاموشی مدل یا JSON نامعتبر | بازگشت محدود و صریح به راهنما/ابهام‌زدایی؛ بدون تماس با OpenAI |

## گام‌های تکمیلی وابسته به داده واقعی

برای تثبیت کیفیت، پرسش‌های واقعی کاربران به‌صورت پالایش‌شده به مجموعه ارزیابی اضافه شوند. ابزارهای جدید آکادمی یا ادمین فقط پس از اتصال واقعی سرویس و دسترسی معتبر اضافه شوند. تغییر هر صفحه یا قانون با به‌روزرسانی مقاله و فرایند مربوط همراه باشد. اجرای خودکار رزرو، لغو و پرداخت در این نسخه پیاده نشده و نیازمند طراحی مستقل پیش‌نمایش، تأیید، جلوگیری از تکرار و ممیزی است.

## نتیجه اعتبارسنجی این تحویل

- کل API: ۲۲ مجموعه و ۱۳۵ تست موفق؛ شامل کنترل دسترسی، رزرو، حافظه گفتگو، خطاهای مدل، خروجی نامعتبر، Context فرم و حفظ تاریخ/فیلتر در ادامه گفتگو.
- SDK و نمایش کارت: ۹ تست هسته و یک تست رندر React موفق.
- کامپایل API و هر سه بسته دستیار موفق؛ بیلد تولید وب با ۴۴ مسیر و پنل ادمین با ۲۰ مسیر موفق.
- درخواست واقعی HTTP بومی Ollama با پاسخ آزمایشی محلی بررسی شد؛ وزن Qwen اجرا نشده و ارزیابی کیفیت فارسی/زمان پاسخ انجام نشده است.
- مرورگر Chromium در محیط موجود نبود و دریافت آن موفق نشد؛ تست کامل تعاملی مرورگر انجام نشده است. رندر React، پاک‌سازی لینک‌ها و چرخه Context با تست‌های مستقل بررسی شدند.
- Docker در محیط در دسترس نبود؛ ساخت ایمیج، اجرای مدل و استقرار روی سرور این تحویل انجام نشده‌اند.

این پچ برای کد دارای ماژول میمو تهیه شده است، نه برای نسخه قدیمی قبل از نصب میمو. فایل‌های .env، داده‌ها و تنظیمات محلی Docker سرور باید حفظ شوند. ابزار بازیابی Redis مربوط به تعمیر قبلی، جزو این ارتقا نیست و اجرا نمی‌شود.
