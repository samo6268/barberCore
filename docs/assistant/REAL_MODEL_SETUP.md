# میمو: اتصال مدل واقعی و داده‌های پرنگارین

این نسخه پاسخ‌های قاعده‌محور را حذف می‌کند و به یک ارائه‌دهنده سازگار با Responses API متصل می‌شود. بدون تنظیم کلید و مدل، پاسخ ساختگی یا نمایشی داده نمی‌شود و پیام تنظیم‌نبودن سرویس نمایش داده خواهد شد.

## فعال‌سازی روی مک

پس از اعمال پچ، در ریشه پروژه اجرا کنید:

```bash
npm install
node scripts/configure-mimo.mjs
```

اسکریپت به ترتیب کلید API، نام مدل و آدرس سرویس را می‌پرسد. کلید در Terminal نمایش داده نمی‌شود؛ تنظیمات با سطح دسترسی 600 در `.env` و `apps/api/.env` نوشته می‌شوند. سایر متغیرهای موجود حفظ می‌شوند. نام پیش‌فرض قابل تغییر است؛ مدلی را وارد کنید که حساب ارائه‌دهنده شما به آن دسترسی دارد و Function Calling در Responses API را پشتیبانی می‌کند. هیچ درخواست پولی هنگام تنظیم انجام نمی‌شود.

اشتراک ChatGPT به‌تنهایی اعتبار API فراهم نمی‌کند. کلید را در چت، سورس، Git یا متغیرهای `NEXT_PUBLIC_` قرار ندهید.

متغیرهای سمت سرور:

```dotenv
ASSISTANT_API_KEY=YOUR_PROVIDER_KEY
ASSISTANT_MODEL=gpt-5.6-terra
ASSISTANT_API_BASE_URL=https://api.openai.com/v1
ASSISTANT_DAILY_TURN_LIMIT=60
ASSISTANT_PRICE_UNIT=IRR
```

`ASSISTANT_PRICE_UNIT=IRR` یعنی قیمت ذخیره‌شده در دیتابیس ریال است و هنگام پاسخ بر ۱۰ تقسیم می‌شود. فقط اگر داده‌های کسب‌وکار واقعاً تومان هستند، مقدار `IRT` بگذارید. این تنظیم داده دیتابیس را تغییر نمی‌دهد. در رابط قدیمی پروژه بعضی کارت‌ها مبلغ خام را تومان نمایش می‌دهند؛ صحت مبلغ را با رکورد خدمت در دیتابیس بررسی کنید، نه فقط متن کارت.

PostgreSQL و Redis باید بالا باشند. سپس API را متوقف و دوباره اجرا کنید:

```bash
docker compose -f infra/docker/docker-compose.yml up -d postgres redis
npm run dev --workspace api
```

در Terminal دیگر:

```bash
npm run dev --workspace web
```

بررسی آمادگی تنظیمات:

```bash
curl -sS http://localhost:4000/api/v1/assistant/status
```

`ready: true` فقط به معنی وجود کلید و نام مدل است؛ اعتبار، دسترسی شبکه و اعتبار مالی ارائه‌دهنده با اولین سؤال واقعی بررسی می‌شوند.

آزمون عمومی بدون ورود:

```bash
curl -sS http://localhost:4000/api/v1/assistant/chat \
  -H 'Content-Type: application/json' \
  -d '{"assistantId":"parnegarin","message":"برای کوتاهی مو در تهران چند سالن پیشنهاد بده","context":{"route":"/salons"}}'
```

آزمون چندمرحله‌ای را از داخل ویجت انجام دهید تا توکن نشست و شناسه گفتگو خودکار منتقل شوند. برای اطلاعات شخصی ابتدا در سامانه وارد شوید. دکمه «گفتگوی تازه» تاریخچه نمایشی را پاک و گفتگوی جدید ایجاد می‌کند؛ تاریخچه قبلی در سرور با انقضا حذف می‌شود.

## چه سؤال‌هایی پاسخ داده می‌شوند؟

| گروه | ابزار و رفتار |
| --- | --- |
| راهنمای سامانه | دانش منتخب معرفی، رزرو، جست‌وجوی نقشه، پروفایل، مدیریت سالن، متخصص، نظرها و آکادمی |
| کشف سالن | فقط سالن فعال و حذف‌نشده، جست‌وجوی شهر، خدمت و جنسیت |
| جزئیات سالن | خدمت، قیمت، مدت، متخصصان و نظرهای قابل نمایش |
| تقویم فارسی | تاریخ امروز تا ۳۰ روز آینده، نام روز و معادل میلادی به وقت تهران |
| وقت آزاد | استعلام از AvailabilityService، روز میلادی و ساعت تهران، تا ۶۰ روز آینده |
| نوبت‌های من | حداکثر پنج نوبت اخیر کاربر احرازشده |
| مدیر سالن | سالن‌های خودش و آمار روزانه با بررسی مجدد مالکیت |
| متخصص | عضویت‌های خودش و برنامه روزانه با بررسی مجدد عضویت |

نتیجه ابزارها منبع لینک‌دار دارد. داده‌ای مثل کد OTP، تلفن مشتریان، اطلاعات کارت، رمز و کلید مدل به ابزارهای دستیار داده نمی‌شود. خدمت یا سالن بدون داده فعال پیشنهاد قطعی نمی‌شود. وقت آزاد به معنی رزرو قطعی نیست. درخواست‌های پزشکی تشخیصی یا خارج حوزه به مسیر مناسب هدایت می‌شوند.

ماژول آموزشی، تسویه جزئی، پرداخت و عملیات تغییردهنده در این نسخه ابزار اجرایی ندارند. دستیار برای این موارد فقط راهنمایی می‌کند؛ نباید ثبت رزرو، لغو یا پرداخت را ادعا کند.

## تاریخچه و محدودیت مصرف

- تاریخچه سمت سرور در Redis، با انقضای یک ساعت پس از آخرین نوبت موفق گفتگو است.
- حداکثر ۱۲ پیام اخیر و حدود ۲۴ هزار نویسه از تاریخچه نگهداری می‌شود.
- مهمان توکن امضاشده مخصوص همان کسب‌وکار دریافت می‌کند؛ شناسه گفتگو به‌تنهایی مجوز دسترسی نیست.
- هویت و نقش مرورگر صرفاً Hint است؛ مجوز از JWT معتبر و نقش فعلی دیتابیس استخراج می‌شود.
- هر ابزار خصوصی مجوز را دوباره در سرویس دامنه بررسی می‌کند.
- برای هر گفتگو قفل هم‌زمانی، برای درخواست‌ها محدودیت IP و برای نشست‌ها سهمیه روزانه وجود دارد.
- هر پاسخ حداکثر چهار Tool Call و پنج درخواست مدل دارد؛ دور آخر فقط برای پاسخ نهایی است.
- مهلت ارتباط مدل ۴۵ ثانیه و سقف خروجی هر درخواست ۳۰۰۰ توکن است. خروجی استدلالی نیز در سقف مدل محاسبه می‌شود.
- در اتصال مرجع پرنگارین، درخواست‌ها از API Client موجود عبور می‌کنند تا Refresh Token مانند سایر صفحات انجام شود. در میزبان‌های دیگر، tokenProvider باید توکن معتبر یا Callback نوسازی توکن ارائه دهد.
- پشت Nginx یا Reverse Proxy باید IP واقعی از پراکسی مورد اعتماد به API منتقل شود؛ در غیر این صورت محدودیت IP ممکن است بین کاربران مشترک شود. هدر دلخواه کاربر، مدرک IP معتبر نیست.
- محدودیت IP فعلی در حافظه همان API Instance است؛ برای چند Instance باید ذخیره‌ساز Throttler مشترک اضافه شود.
- `store:false` از ذخیره وضعیت Responses برای ادامه گفتگو استفاده نمی‌کند؛ این گزینه به معنی Zero Data Retention کامل ارائه‌دهنده نیست. پیام، سابقه لازم و نتیجه ابزار برای پردازش به ارائه‌دهنده ارسال می‌شوند.
- لاگ‌های جدید فقط متادیتای زمان، وضعیت و نام کسب‌وکار را ثبت می‌کنند؛ بدنه، کلید و خروجی ابزار لاگ نمی‌شوند. تنظیم Redaction برای Authorization و Cookie نیز به لاگر اصلی اضافه شده است.

## استفاده در کسب‌وکارهای دیگر

Business Manifest فرانت‌اند، ظاهر و واژگان را تعیین می‌کند. ثبت کسب‌وکار در سرور جداست تا کاربر نتواند با ارسال شناسه دلخواه به داده پرنگارین دسترسی بگیرد.

نمونه متغیر سمت سرور (JSON یک‌خطی):

```dotenv
ASSISTANT_BUSINESSES_JSON='[{"assistantId":"example-app","name":"سامانه نمونه","description":"خدمات سازمانی","knowledge":[{"id":"guide","title":"راهنمای ثبت درخواست","text":"برای ثبت درخواست به صفحه درخواست‌ها بروید.","path":"/requests"}]}]'
```

برای این کسب‌وکار، در ویجت `assistantId` و `businessId` را `example-app` قرار دهید. این نصب فقط دانش همان برند و ابزار عمومی تقویم را دارد؛ Toolهای پرنگارین برای آن فعال نمی‌شوند. برای اتصال اطلاعات عملیاتی سامانه دیگر، Adapter احراز هویت و Toolهای خواندنی همان سامانه باید به Registry سمت سرور اضافه شوند. ارسال نقش یا tenantId از مرورگر، جای این Adapter را نمی‌گیرد. مبدأ دامنه ویجت نیز باید در CORS سرویس Gateway مجاز باشد؛ CORS فعلی پرنگارین بر اساس `APP_URL` است.

در سامانه میزبان، هنگام ورود، خروج یا تعویض حساب، React Provider را با `key` هویت جدید Mount کنید. در Web Component، `configure` را با هویت جدید فراخوانی کنید تا تاریخچه و پاسخ در حال دریافت حساب قبلی به حساب جدید منتقل نشود.

## استقرار Docker

فایل Compose فعلی سرور و اصلاحات محلی آن را جایگزین نکنید. Override دستیار را اضافه کنید:

```bash
docker compose --env-file .env \
  -f infra/docker/docker-compose.yml \
  -f infra/docker/docker-compose.assistant.yml \
  --profile full up -d --build api web
```

قبل از استقرار، تنظیمات سروری قبلی، بکاپ و متغیرهای شبکه باید حفظ شوند. این پچ Migration جدید ندارد.

## اعتبارسنجی

```bash
npm test --workspace api -- --runInBand src/modules/assistant
npm run build --workspace api
npm run build --workspace web
```

تست‌های Provider شامل سرویس HTTP آزمایشی محلی، قرارداد Function Calling، عدم ذخیره Responses، ابزارهای نامعتبر و سقف اجرا هستند. آزمون زنده با حساب پولی فقط بعد از تنظیم کلید شما انجام می‌شود و با آزمون شبیه‌سازی‌شده یکسان نیست.
